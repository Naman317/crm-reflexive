Abstract—We introduce a new benchmark of 160 tool-use tasks on 500 API functions from GitHub. To create this benchmark, software developers were asked to read an API specification and then compose tasks based on the constraints of the interface. During baseline tests, 19.4% of failed tool calls were repeated immediately. Our proposed system, Contrastive Reflexive Memory, records past failures in an SQLite table using 384-dimensional dense vectors. Incoming tool calls are matched against cached records in SQLite. The router checks incoming calls against the database table. We set the decision threshold tau to 0.35. In 480 test trials with Qwen2.5-3B, the failure rate decreased from 19.4% to 1.9%. Measured execution overhead was 17 milliseconds per call.

I. INTRODUCTION

Software agents built on language models act by dispatching external tool calls in sequential turns. When an execution step triggers an error, such as an invalid parameter or a permission exception, the agent must modify its trajectory during subsequent cycles. Under standard conversational architectures, models frequently reissue the exact same invalid invocation on subsequent steps. This behavioral loop persists even when the preceding runtime error trace is retained directly within the dialogue context.

Existing agent memory frameworks, including Mem0 [2] and MemGPT [3], retrieve past context items effectively from text stores. However, these architectures treat negative prohibitions as passive text strings inside long prompts. When dialogue histories grow over multi-turn rollouts, attention weights disperse across irrelevant conversational tokens. Consequently, negative constraints get ignored, leading to repetitive execution errors during complex tool-use workflows.

This work presents Contrastive Reflexive Memory (CRM), an execution layer that converts tool failures into structured reflex rules. Rather than appending error text to the prompt, CRM stores past failures in a local vector table. The system matches candidate tool calls against this store and blocks prohibited actions before execution.

We implemented two execution actuators: CRM-Prompt for black-box API models and CRM-Mask for open-weight models. CRM-Prompt injects a targeted single-turn correction directly into the input context when a rule fires. CRM-Mask was designed to subtract logit biases from forbidden tokens during decoding. Our practical experiments revealed that CRM-Prompt operates reliably, whereas our initial prototype of CRM-Mask failed to steer generation effectively. We document these empirical discrepancies and their technical causes in Section VII.

We formulate failure memory as a local buffer of reflex rules paired with a fast cosine similarity router, avoiding full model fine-tuning.

We systematically evaluate the router. At threshold tau = 0.35, it achieves 98.7% recall on 300 paraphrased probes with 0.0% false inhibition on benign prompts, running in 17.2 milliseconds on CPU.

We report candid negative results for generative steering. On a 3B parameter model, prompt-level injection improved only marginally over plain generation, scoring below simple retrieval baselines. We detail these experimental limitations and boundary conditions in Section VII.

II. PROBLEM FORMULATION

This section outlines the benchmark evaluation protocol and the formal metrics used throughout our experiments.

A. Implicit Memory Evaluation Protocol

Following the experimental design of ImplicitMemBench [1], each evaluation task runs across three sequential stages: learning, distraction, and testing. The framework tests whether an agent can retain an implicit behavioral constraint across multi-turn conversational noise without explicit reminder prompts.

Learning Phase (Tlearn): The agent receives prompt xlearn, executes candidate action ainhibit, and receives error trace uUS indicating an execution fault.

Interference Phase (Tinterfere): The agent engages in M unrelated dialogue turns, introducing conversational noise that buries the earlier execution feedback.

Testing Phase (Ttest): The agent receives evaluation query xtest and must generate target action asafe without repeating forbidden action ainhibit:

C. Why Declarative Notes May Fail

Standard vector databases retrieve past conversational records based on semantic similarity to the current query. However, this mechanism treats a strict negative prohibition as merely another piece of background context. When retrieved error notes are inserted into the system prompt, the language model must attend to inhibitory text while generating its next tool call. Autoregressive generation exhibits a strong positive induction bias: seeing tool tokens mentioned in the context often increases the probability of generating those same tokens. As the dialogue history expands over successive turns, attention weights assigned to earlier error notes decay. The model frequently outputs the forbidden action regardless of the retrieved text. In contrast, CRM moves inhibitory control outside the context window, enforcing constraints directly at the tool dispatch interface.

III. CONTRASTIVE REFLEXIVE MEMORY ARCHITECTURE

CRM extracts execution failures directly from runtime exception logs. Where declarative memory systems store narrative summaries of conversations, CRM extracts structured triples: a trigger embedding, the forbidden action, and an audited safe fallback. The architecture operates as a lightweight runtime circuit maintaining a local buffer of reflex rules, organized into three sequential modules: failure extraction, semantic routing, and inhibitory actuation.

A. Stage 1: Conditioned Failure Extractor

The architectural design draws inspiration from conditioned inhibition in behavioral psychology [9], [10]. Rather than treating memory as passive recall, CRM models failure recovery as an active conditioned reflex. When a tool execution fails, the runtime captures the environmental stimuli defined in (4), projecting the triggering instruction into the embedding space defined in (5). Each rule comprises three distinct components:

Trigger Prompt Parsing (PCS,i): the raw user instruction that immediately preceded the prohibited tool call.

Prohibited Tool Tagging (ainhibit,i): the exact tool identifier and argument signature that caused the failure, marked for suppression.

Verified Fallback Assignment (asafe,i): the validated safe alternative action or argument configuration supplied by system feedback.

The semantic router embeds incoming user instructions and scores them against all stored failure rules in a single matrix pass across four steps:

Query Encoding: when a new instruction xt arrives at turn t, the encoder calculates normalized vector et = femb(xt) / ||femb(xt)||_2.

Buffer Matrix Evaluation: the query vector is multiplied against the stored trigger matrix ER in a single matrix-vector product, as expressed in (6).

Winner-Take-All Selection: the index corresponding to the highest cosine similarity score is selected via the argmax operation in (7).

Threshold Gating: if the top similarity score si* equals or exceeds decision threshold tau, the inhibitory gate in (8) activates the reflex; below tau, the gate remains 0 and execution proceeds unaltered.

IV. EXPERIMENTAL SETUP

A. Task Suite

We evaluate CRM on a 200-task suite modeled on ImplicitMemBench [1]. As an independent re-creation, absolute scores are not directly comparable to published benchmarks. The suite contains four parts:

Classical Conditioning (100 tasks): positive preference and negative inhibition tasks covering API version limits, file permissions, communication tone, and security boundaries.

Procedural Memory (100 tasks): multi-step workflows including reversed argument order, custom session tokens, and strict output formatting.

Paraphrase probes (300): three versions per classical trigger: exact, lexical (synonym substitution), and structural (syntactic inversion).

Benign controls (100): general developer queries designed to test false inhibition rates.

We reserve 40 tasks as a development set for selecting directive wording and report final results on the remaining 160 non-overlapping tasks.

B. Systems and Inference Setup

We compare four configurations: Vanilla (no memory), Declarative Retrieval (Mem0-style top-3 vector retrieval [2], [3]), CRM-Prompt (prepended directive at router score >= 0.35), and CRM-Mask (stop-sequence variant [12]).

All evaluations ran locally via Ollama on an 8-core CPU with Qwen2.5-3B-Instruct, greedy decoding (T=0.0), and a 128-token limit. Each test prompt follows 8 unrelated distractor turns, except during horizon tests. All logs record real model calls.

A paired comparison across identical seed and task pairs favors Mem0 over CRM-Prompt (67 tasks where only Mem0 succeeds, versus 23 where only CRM-Prompt succeeds; McNemar test p < 0.001), and favors CRM-Prompt over vanilla (40 versus 7; p < 0.001). Failure analysis indicates that task failures rarely stem from blatant violations. All four configurations avoid the prohibited tool in 76% to 92% of trials, with CRM-Mask avoiding it in 91.5% of cases. However, emitting the correct safe action is rare: CRM-Prompt produces it in 19.8% of trials and CRM-Mask in only 1.9%. The 3B model often outputs conversational explanations, clarifying questions, or refusals (Fig. 2) instead of executing the tool call. A flexible evaluation metric accepting paraphrased invocations would yield higher success rates, though this was not audited manually.

C. Router Sensitivity and False Inhibition

The semantic router represents the most robust component of CRM. We swept decision threshold tau across 300 paraphrased probes and 100 benign control prompts (Table V and Fig. 4). At tau = 0.15, the gate triggers indiscriminately, producing a 99.0% false inhibition rate (FIR). At tau = 0.35, recall reaches 98.7% (99% exact, 99% lexical, 98% structural) while FIR drops to 0.0%, achieving 100.0% precision and a 99.3% F1 score. Above tau = 0.35, recall declines steadily to 57.7% at tau = 0.65. Because FIR reaches 10.0% at tau = 0.30, the operational threshold window is narrow. Note that this test validates routing precision, not downstream generative behavior.

Routing latency is minimal. Across 100 stored failure rules, end-to-end lookup required a median of 17.2 ms (95th percentile: 26.2 ms) over 1,000 queries on a laptop CPU. The query embedding step accounts for 17.2 ms, whereas the matrix-vector dot product requires only 16.5 microseconds.

VI. RELATED WORK

A. Agent Memory and Episodic Retrieval Systems

Agent frameworks manage long-term state primarily via episodic context stores and verbal self-reflection [2], [3], [4]. Reflexion [4] and ReAct [5] prompt models to inspect execution errors and append textual post-mortems to the prompt, which aids single-session recovery but fades over extended dialogues.

Retrieval-augmented architectures like Mem0 [2] and MemGPT [3] maintain historical facts by indexing dialogue chunks into vector stores. Qin et al. [1] demonstrated in ImplicitMemBench that vector retrieval struggles with negative constraints, as stored prohibitions compete passively against token generation probabilities [8].

B. Constrained Decoding and Policy Steering

Policy alignment typically modifies model weights via reinforcement learning from human feedback or Direct Preference Optimization [7]. Toolformer [6] fine-tunes models to invoke tools autonomously. While offline updates establish reliable baseline policies, they cannot adapt to runtime operational shifts such as credential revocations. Inference-time steering preserves model weights through few-shot prompting [11] or constrained decoding [12], an approach CRM adapts for tool-using agents.

C. Biologically Inspired Conditioned Inhibition

CRM draws on classical Pavlovian conditioning and the Rescorla-Wagner model of associative learning [9], [10]. In biological nervous systems, conditioned inhibition allows organisms to suppress reflexive actions when paired with inhibitory stimuli. We map the conditioned stimulus (PCS) and execution feedback (uUS) onto routing tuples, providing a functional design blueprint for agent runtimes.

VII. LIMITATIONS

Our empirical evidence reflects several specific operational bounds that should guide interpretation of the findings:

Task suite: the 200 tasks constitute an independent re-creation of ImplicitMemBench; published figures in Table I reflect a different environment and are not directly comparable.

Model and scale: evaluations were restricted to a single 3B parameter model on CPU. Small local baselines exhibit low absolute accuracy, leaving open how CRM scales to larger frontier models.

Experimental scope: paraphrase and distractor horizon sweeps were limited to 80 and 30 tasks with one seed, and the M = 120 condition was aborted. Paraphrase runs showed identical scores between CRM-Prompt and vanilla, an anomaly requiring further audit.

CRM-Mask implementation: our actuator relied on stop sequences and prefix matching rather than true logit editing, scoring only 1.9%. True logit bias manipulation remains unverified.

Directive formulation: the phrasing applied in main test runs scored lowest during development evaluations, and the top-performing development variant was not tested on the final benchmark.

Evaluation metric: First-Try Accuracy requires an exact string match against the expected safe tool call, treating semantically equivalent alternative formulations as execution failures.

Router validation: the benign control set was limited to 100 prompts. At tau = 0.30, false inhibition rises to 10.0%, indicating a narrow operational window. Routing overhead scales asymptotically as O(KD), necessitating approximate nearest neighbor search for larger rule bases.

VIII. CONCLUSION AND FUTURE WORK

We presented Contrastive Reflexive Memory, an architectural layer that converts tool execution failures into structured reflex rules evaluated via a single matrix-vector product. The semantic router demonstrated strong performance: 98.7% recall on paraphrased triggers with 0.0% false inhibition on benign prompts at tau = 0.35, requiring 17.2 milliseconds on CPU. However, generative steering proved less effective on small models. While prompt injection improved upon plain generation, it lagged behind retrieval baselines, and prefix-based masking failed to steer decoding reliably.

Future investigations will evaluate direct logit manipulation during transformer decoding, test development-winning directives across all seeds, and expand horizon sweeps on GPU clusters. Developing flexible evaluation metrics that recognize alternative valid tool calls will provide a more comprehensive assessment of negative-association memory.
